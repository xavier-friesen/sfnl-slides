# Runtime dependencies for the sfnl-powerpoint scripts.
#
#   <PYEXE> -m pip install -r requirements.txt
#
# Resolve <PYEXE> first: try python3, then python, then py -3, and treat the Windows
# Store stub as NOT FOUND (it prints "Python was not found" and exits non-zero).
# scripts/preflight.py reports which of these are importable and which renderers exist.

# Reads and writes the deck. Pinned to the major/minor we tested against: the
# placeholder-inheritance behaviour add_slide.py and _deck.py rely on is not stable
# across majors.
python-pptx>=1.0,<2.0

# All hand-editing of slide XML goes through lxml. Needed for the XSD validation in
# office/validators too, which the stdlib ElementTree cannot do.
lxml>=5.0

# Parses untrusted XML in clean.py and the validators without the entity-expansion
# and quadratic-blowup exposure of the stdlib parsers.
defusedxml>=0.7

# PowerPoint COM, the preferred renderer: it is the engine the client opens the deck
# in, so Gotham, Montserrat and Lato measure exactly right. Windows only; every other
# platform falls back to LibreOffice, or to QA-only mode when that is absent too.
pywin32>=306; sys_platform == "win32"

# Alleen als je zelf tests schrijft. Deze plugin-repo draagt geen testsuite en geen
# pytest.ini; de scripts documenteren hun eigen metingen in de docstring.
pytest>=8.0

# thumbnail.py composes the labelled contact sheet from the rendered PNGs.
pillow>=10.0

# --- sfnl-design-documents ---

# De renderloop en alle metingen van het documentskill draaien in een echte browser:
# render.py maakt de PNG's en het contactblad, qa_document.py meet overloop, klipping
# en gaten in het DOM zelf. Zonder dit bouw je blind, en dat is een andere manier
# van bouwen — zie "Zonder renderer" in skills/sfnl-design-documents/SKILL.md.
#
# Staat er al een Chromium op de machine (PLAYWRIGHT_BROWSERS_PATH), dan zoekt
# scripts/documenten/_browser.py hem op, ook als het buildnummer niet bij deze
# pip-versie hoort. Anders: python3 -m playwright install chromium
playwright>=1.40

# --- sfnl-rapport-opmaak ---
#
# Deze skill heeft geen eigen afhankelijkheden bovenop wat er hierboven al
# staat, en dat is opzet.
#
# `lees_docx.py` leest een .docx met `zipfile` en `xml.etree` uit de
# stdlib en niet met python-docx. Een .docx is een zip met XML erin, de
# stdlib kan dat, en het scheelt niet alleen een afhankelijkheid: het is
# meteen duidelijk uit welk element welk stuk tekst komt, en dat is precies
# wat je wilt kunnen navertellen wanneer `tekstcheck.py` een afwijking
# meldt.
#
# Wat de skill wél nodig heeft is `playwright` hierboven, en die is hier
# geen luxe. Een alinea op een regelgrens splitsen kan alleen een engine
# die weet hoe breed een woord is, dus anders dan bij
# sfnl-design-documents is er hier geen "zonder renderer bouw je blind"-
# route: zonder browser is er geen route. `preflight.py` blokkeert erop.

# --- sfnl-infographic ---
#
# fontTools leest de fontbestanden waarmee svg.py de regelafbreking rekent, en
# instantieert het variabele Montserrat op 300 en 600. Zonder deze module is de
# afbreking een schatting: compositie en kleur beoordeel je dan gewoon op de
# render, regelval en blokhoogte niet.
fonttools>=4.40

# En brotli hoort erbij, want de letters die de plugin meedraagt zijn woff2 —
# dezelfde bestanden die assets/documenten/fonts/fonts.css insluit. Een woff2 is
# brotli-gecomprimeerd, dus zonder deze module krijgt fontTools hem niet open en
# zakt de meting stil terug op een schatting terwijl er niets ontbreekt om naar
# te wijzen. Daarom meet scripts/infographic/preflight.py de metriek echt na in
# plaats van te melden dat er een bestand staat.
brotli>=1.0
